# Linear project workflow publication

Publish the existing context and maintenance guidance as Linear Workflows 0.7.0.
Keep this document with the implementation PR.

## Behavior

Check relevant project activity before new or resumed work. Context discovery
is read-only. When authorized work starts on a verified issue, use the team's
actual active-work state before substantive implementation, research or planning.
Review-only requests do not start an issue. Preserve unrelated metadata.

Use project maintenance for authorized cleanup. Compare recorded progress with
acceptance evidence. Keep unmerged implementation open when merge is required.
Preserve requirements, user notes and history. Verify a complete snapshot with
equivalent access before shortening a crowded description. Reconcile concurrent
edits and keep uncertain or racing changes intact. Save the final TL;DR before
an authorized completed-state transition. Repeated unchanged work needs no write.

## Publication work

- Restore the existing skill text without adding new behavior.

- Update paired manifests, catalog membership, documentation and changelog.
- Preserve the original context evaluation as historical evidence.

The package supplies guidance, not a Linear connector, schedule, atomic locking
service or server-enforced workflow. Source checks and simulated choices do not
prove automatic invocation in authenticated host sessions.
